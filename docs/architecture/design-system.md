# Design system: tokens, shadcn, type scale, layout primitives

> For the why behind these rules, see [`../decisions/design-system.md`](../decisions/design-system.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- **Design tokens live in `app/globals.css`** as Tailwind v4 `@theme` variables — this project has **no `tailwind.config.ts`**. Fonts (Bricolage Grotesque for display, Archivo for UI/body) load via `next/font/google` in `app/layout.tsx`. Extend the `@theme` block; never hardcode hex values in components. One token deliberately diverges from the handoff: **`--color-muted` was darkened to `#6e6b60`** because the original failed WCAG AA on every ground it is used against.
- **There are TWO type systems in this repo, and `font-marketing` is the boundary.** The authenticated app is Bricolage + Archivo on the named `--text-*` scale. **The public marketing surface — `/`, `/planos`, `/privacy`, `/terms` — is Geist alone on Tailwind's own default type scale**, with spacing restricted to the `landing-page-design` skill's B2 table and motion on one named easing curve (`--ease-fluid`). Everything under `components/landing`, `components/pricing` and `components/legal` renders inside `MarketingShell`, which applies `font-marketing`; **nothing outside those three directories may reach for it, and nothing inside them may reach for `font-display` or a `--text-*` step.** `components/landing/marketingDesignSystem.test.ts` enforces all of that by reading the source, so a new marketing section is covered the day it is written. The third font (`Geist`) is loaded alongside the other two in `app/layout.tsx`.
  - **This is a deliberate, documented divergence from `docs/design/`, not drift.** `docs/design/screens/Landing.dc.html` and `Planos.dc.html` describe the _old_ system for those two screens, and the screenshot-alignment pass must **not** "fix" the marketing surface back toward them. Every other screen's `.dc.html` is the reference to build against — the reference, not the verdict; see [`design-handoff.md`](design-handoff.md).
- **shadcn/ui is installed, but the MoldAI tokens stay the source of truth.**
  - **Never run `shadcn init`, `shadcn apply <preset>`, or `init --preset`** — each overwrites the `@theme` block and components, wiping the alias layer. `components.json` is hand-written.
  - shadcn's semantic names exist only as a **second `@theme inline` block aliasing the MoldAI tokens** — never give one a literal value. **`--color-border` and `--color-muted` are deliberately not aliased**: shadcn means a _surface_ by "muted" where this repo means _text_, so a ported component's `bg-muted` becomes `bg-surface-alt` while `text-muted-foreground` maps through as-is.
  - The app is **light-only**: `@custom-variant dark (&:is(.dark *))` keeps shadcn's `dark:` classes inert. Without it Tailwind v4 fires them on `prefers-color-scheme` and a dark-OS visitor gets half-dark controls on a light page.
  - **Every screen consumes these primitives — a raw `<button>` is the deliberate exception, not the default, and each one should be a clickable _region_ or an ARIA-role-bearing option rather than a plain control** (the pattern thumbnail, the paywall plan cards, the multi-line size-chart rows, `ImportSizeChartDialog`'s dashed trigger card, `PatternGrid`'s dashboard import card, `OnboardingShell`'s steps, and a handful more — grep `<button` outside `components/ui/` rather than trusting a count or list here to stay current). A new plain `<button>` needs to clear that bar or it should be a `Button`.
  - **Tune a primitive in `components/ui/`, never with per-call-site `className` overrides.** That is where the extra `Button` sizes/variants (`chrome`, `accent`, `soft`, `destructiveOutline`) and `Badge`'s `size="chip"`/`soon` live — **including the marketing surface's `marketing`/`marketingSm` sizes** (rounded-full, B2's 8px/12px padding, `text-base`/`text-sm`, `active:scale-[0.98]`), which exist precisely so `/` and `/planos` do not override the primitive per call site.
  - **The chat stream is `bubble` + `marker`,** whose variants are the design's own: `default` (olive, the user), `paper` (the AI), `notice` (amber — a seam conflict, failed generation, or size-chart substitution; deliberately **not** `destructive`, the red alert token), `surface` (white, for a bubble holding controls). `ChatMessage.tone` keeps `"notice"` and `"conflict"` distinct in the data model because an informational caveat is not a seam conflict.
  - **`ScrollArea` carries two local additions, both forced by Radix:** `viewportRef` (the scrolling element is the viewport, not the Root) and `fill` (Radix's inline `display:table` box has no definite height and collapses a `flex-1` child). `PatternGrid` deliberately does **not** use `fill`. Its thumb is `bg-muted` rather than shadcn's `bg-border` — a draggable thumb owes WCAG 1.4.11's 3:1, and `--color-border` reads 1.26:1 on paper.
  - **After any `shadcn add`:** review the `app/globals.css` diff (`cssVariables: true` lets the CLI inject into it) and run `npm run format`. `components.json` carries **no `registries` map on purpose** — `@shadcn` is built-in and hand-writing its URL would shadow it with a broken one; pass `registries: ["@shadcn"]` to the MCP tools instead.
- **Type comes from the named scale, never `text-[Npx]`.** `app/globals.css` defines 8 steps as `--text-*` tokens — `text-tick` (10.5px) · `text-meta` (11.5) · `text-ui` (12.5, the default UI size) · `text-control` (13.5, buttons/inputs/tabs) · `text-body` (16) · `text-title` (21) · `text-display` (26) · `text-hero` (54). **This scale governs the authenticated app only** — the marketing surface is on Tailwind's default scale (see the two-type-systems rule above), so `text-hero`/`tracking-hero` no longer have any consumer and are kept only as tokens pending a decision to delete them. Uppercase labels take `tracking-eyebrow`; the wordmark's tightening is `tracking-wordmark` and the landing hero's is `tracking-hero`, each named after its only user. Body text is `font-normal` — `font-semibold` had spread to 85 call sites and stopped meaning emphasis. **The sweep is finished and staying at zero is the rule:** `app/` and `components/` hold no `text-[Npx]` and no bracketed tracking, and **the shadcn primitives carry no stock Tailwind size either** (`text-sm`/`xs`/`base`/`lg` → `text-control`/`text-ui`/`text-meta`/`text-body`), because a 14px shadcn default is out of scale against a 12.5px UI. **A glyph used as an icon is sized as an icon** (lucide + `size-*`, or `EmptyMedia`), never priced on the type scale.
- **An icon with no text beside it always carries a tooltip.** Any icon-only control gets BOTH `aria-label` (the accessible name) and `title` (the hover tooltip), resolved from the same catalog key — an icon that is obvious to the person who chose it is a guess for everyone else, and `aria-label` alone leaves sighted mouse users with nothing. This covers every icon-only `Button` (the editor's canvas chrome and composer attachment row, the dashboard/checklist dismiss "X"s, `PatternCard`'s "⋯", `PieceDetailsPanel`'s close, `AppShell`'s nav toggle, `PageHeader`'s back chevron) and is the reason a control that loses its visible label to a design change must gain the tooltip in the same edit. An icon that sits next to its own text label needs neither.
- **Every full-page screen renders through `components/shared/AppShell.tsx`**, with one exception: `/login`, `/signup`, `/verify` and `/onboarding` are centered-card screens with no header, rendering their own `Wordmark`. `AppShell` owns the page frame and builds `PageHeader` itself from plain data props, so a screen cannot hand-roll a header. Three `PageHeader` props are optional, all three because of the dashboard: `backHref` (it **is** `/`), `title` (the sidebar already marks the section), and `credits` (nullable because the balance arrives after first paint — the bar is simply absent until it lands rather than flickering in; if the summary fetch fails it stays null for good, and the content region's error message is what keeps that from being silent). **The credits chip is a single compact ~30px pill** — it has regressed once into a two-line block with a full-width bar and a separate button, which affected every authenticated screen at once since `PageHeader` is shared; keep it to the one-pill shape. **There is no global nav sidebar** — `sidebar` is whatever column the screen owns, and `AppShell` renders it bare, so **a new sidebar-bearing screen must set its own width**, and there are deliberately **two** of them: the nav sidebar is **200px** (`Dashboard`/`Bases do atelie`/`Medidas e grades`.dc.html all agree) and `/settings`' section list is **172px** (`Configuracoes.dc.html`). **The editor's header persists through every one of its own pre-ready states** (loading, load error, desktop-only) — `EditorShell` renders `AppShell` in all of them rather than an early-return bare `<div>`, with `title` simply omitted until the pattern's name is known (the same "absent is valid" rule the dashboard's title-less header already relies on) — the loading state additionally gets a skeleton layout instead of plain centered text.
- **A display name that reaches a layout needs a cap _and_ a truncation.** `MAX_PATTERN_NAME_LENGTH` (`lib/types.ts`) is enforced by the API and reused as the rename dialog's `maxLength`, so the field stops you before the round trip does. Both `PageHeader`'s title and `PatternCard`'s name `truncate` with **`min-w-0` on the flex column** — without it there is nothing for `truncate` to shrink against and the overflow just shoves its siblings.
- **A control must not rewrite what you typed.** `MeasurementCell` holds in-progress text locally and commits only on blur/Enter, only when it parses and is in range; out-of-range gets `aria-invalid` plus a message naming the accepted range (lifted to the table — a 56px column has no room), and Escape restores. The progression-rule input is deliberately untouched: it isn't clamped on display, so it has no feedback loop, and `0` is a meaningful rule value.
