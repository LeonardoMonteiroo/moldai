# Testing conventions

> For the why behind these rules, see [`../decisions/testing.md`](../decisions/testing.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- **`.claude/hooks/check-conventions.mjs` is not a complete audit — a manual pass still matters.** Its hardcoded-pt-BR (CHECK 1) and hex-color (CHECK 2) checks scan `.tsx` **and `.ts`** (each with a `lib/` exemption list for modules baking text/color into an exported _file_ rather than the UI — `lib/brand/og.ts` is on CHECK 2's list because the Open Graph card is drawn by satori, outside the browser and outside the stylesheet, where `var(--color-*)` resolves to nothing), CHECK 3 catches direct `fetch(`, and its i18n key-existence check (CHECK 4) **matches only a literal `t("…")` first argument** — it cannot evaluate a template-built key.
- **Component tests are the `dom` vitest project** — jsdom + RTL, configured in `vitest.workspace.ts` as a **second project** so the pure-logic `node` suite never loads the DOM setup file. `vitest.setup.ts` installs the jest-dom matchers, RTL auto-cleanup, and the browser APIs jsdom lacks that Radix calls (`ResizeObserver`, pointer capture, `scrollIntoView`, `matchMedia`) — **a Radix component that will not open in a test is almost always a missing one of those, not a broken assertion.**
  - Render through `renderWithIntl` (`components/test-utils.tsx`), which wraps the tree in the **real** `messages/pt-BR.json`. **But next-intl does not throw on a missing key** — it renders the literal key path, logs `IntlError: MISSING_MESSAGE`, and **the test still passes**. An assertion matching a substring, a regex, or the key name is therefore **vacuous**. Catalog-text assertions must compare against the exact resolved `ptBR` value.
  - **Assert against the exported `ptBR` catalog object, never a pasted pt-BR literal** — the no-hardcoded-display-text rule applies to tests, and it makes a copy change a one-place edit. That governs _catalog text_, not _test data_: arbitrary strings passed in as fixture props are fine as plain literals.
- **A `vi.mock(...)` call must use the exact specifier the subject module itself imports** — never assume `@/...` and a relative path to the same file are interchangeable. If the subject imports `./prisma` and the test mocks `"@/lib/db/prisma"`, both must independently resolve to the same absolute path, and **if that resolution is ever wrong the mismatch is silent**: the mock never intercepts, the real dependency runs, and the test's own assertions report zero calls instead of an error. `lib/db/*.test.ts` all mock `"./prisma"`, matching their subjects exactly; `lib/db/aliasResolution.test.ts` is a standing regression guard pinning the alias-vs-relative collapse.
- **A drafted-outline geometric predicate (self-intersection, containment, degeneracy) has exactly one owner: `lib/draft/geometryPredicates.ts`.** Before #330 each consumer (`lib/draft/spaceSampling.test.ts`, `lib/draft/garment.test.ts`, `lib/export/model.test.ts`) re-derived its own `cross`/`segmentsIntersect`/`hasSelfIntersection`/containment-scanline copy, with a comment in `spaceSampling.test.ts` explicitly defending the duplication as this repo's convention — it wasn't, and that comment is gone. A test file still owns its own **tolerance and assertion message** (`garment.test.ts`'s containment check has no epsilon; `spaceSampling.test.ts`'s and the shared module's own `CONTAINMENT_EPS_CM` is `1e-6`, chosen for the float64-noise reason each carries in its own comment) — it must never re-derive the **predicate** itself. Same footing as `lib/draft/fixtures.ts`: test-only, excluded from `vitest.config.ts`'s coverage `include` for the same "~100% covered by construction inflates the ratchet" reason.
- **Containment is real point-in-polygon (`pointInPolygonCm`, even-odd ray cast, boundary-inclusive), not a vertical min/max scanline band.** The scanline shape (`verticalSpanAt`, still exported for a caller that wants it) is strictly weaker — it only checks a point falls between the outline's topmost/bottommost crossing at that x, which misses a point sitting in a concave void (the bottom of a deep V-neck) or between an outline's own crossings. `garment.test.ts` and `spaceSampling.test.ts` were both migrated to `pointInPolygonCm` in the same pass (#330) and stayed green across the entire `DECORATION_CASES`/sampled-spec matrix with no tolerance loosening needed.
