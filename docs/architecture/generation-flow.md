# Generation flow (`POST /api/patterns/[id]/generate`)

> For the why behind these rules — why `explain` replaced the planned glossary screen, and the attachment-preparation details — see [`../decisions/generation-flow.md`](../decisions/generation-flow.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- Debits `COSTS.adjust` immediately, then `proposeGarment` (`lib/ai/`) asks `claude-sonnet-5`, via **forced tool-use**, for `{ decision: "apply" | "decline" | "ask" | "explain", spec, questions?, declineReason?, assistantMessage, assemblyOrder? }`.
- **`lib/ai/` is split by responsibility, all derived from one source of truth:** `prompt.ts` (sectioned system prompt), `schema.ts` (the `propose_garment` tool), `history.ts` (pure `buildHistory`), `decision.ts` (pure `resolveDecision`), `index.ts` (**the only file importing the SDK**). **The prompt's and schema's every enum and numeric bound render from the active drafting engine's capability** (see [`drafting.md`](drafting.md)) — the same constants `validateSpec` clamps with, so the model is never told a range the validator doesn't enforce. **Add a style field in one place and all three follow. Never hardcode a bound in the prompt or schema.** The rule covers prices and formats too: `# Product facts` renders costs from `COSTS` and formats from `EXPORT_FORMATS`.
- **Trust boundary: the returned `spec` is never trusted as-is.** `validateSpec` re-checks every enum and clamps every numeric field before use; `questions` go through `validateQuestions`. **The same rule covers the _user's_ size-chart patch** (`lib/sizeCharts/validate.ts`) — it was written for the AI's input and initially forgotten on the human's, which reaches the identical drafter.
- **The AI never emits SVG or pixel coordinates — only a `GarmentSpec`.** A `decision: "apply"` carrying no usable `spec` object **throws** rather than letting `validateSpec` fabricate a default blouse; the route's catch refunds the credit.
- **Per decision:** `apply` → `applyGarmentSpec` → `draftGarment` recomputes everything from scratch and bumps the version. `decline`, and any API/parse error, **refunds**. `ask` (underspecified) attaches 1–4 single-choice `questions`, **refunds**, and responds `status: "clarify"` with no draft and no version bump — answering calls `sendMessage(phrase, { answering: true })`, and that flag (server-side enforced) prevents the AI asking again.
- **`explain` is the one non-drafting decision that is NOT refunded.** The user asked a question and got a real answer from a real Anthropic call, where `ask`/`decline` refund precisely because they delivered nothing. `resolveDecision` throws on an `explain` carrying a blank `assistantMessage` — the message _is_ the payload — so the catch refunds rather than charging for an empty bubble. Out-of-scope questions still `decline`.
- **A chat turn can carry up to `MAX_ATTACHMENT_COUNT` (4) photo/sketch attachments, one image block each in the same call — and none of them persisted.** `lib/editor/attachment.ts`'s `prepareImage` downscales each to `MAX_ATTACHMENT_LONG_EDGE_PX` and re-encodes as JPEG client-side, **rejecting an unsupported type or oversized source before any decode work**; `validateAttachmentInputs` is the server-side trust boundary and enforces the count, the per-image `MAX_ATTACHMENT_BASE64_CHARS` and the combined `MAX_ATTACHMENTS_TOTAL_BASE64_CHARS` **before any debit or Anthropic call** — `MAX_GENERATE_BODY_BYTES` is derived from that combined ceiling. The wire field is `images`, an array; there is no singular `image` field any more. The attachments travel only with the request, never into the persisted `PatternState` — only `ChatMessage.hasImage` plus `imageCount` record that they were used. **`hasImage`, `imageCount` and `assembly` must every one be named in `ChatMessageSchema`**: `z.object` strips what it does not name, `toState` returns the stripped object and `savePattern` writes it straight back, so an unlisted message field is deleted from the row by the next mutating turn.
- **The browser's preparation is a UX affordance, not the trust boundary.** The route re-validates `body.images` with `validateAttachmentInputs` **before any debit or Anthropic call**, answering `invalid_attachment` otherwise, and reads its body through a route-local larger `maxBytes` ceiling.
- **A tool payload `resolveDecision` (or the SDK-response check ahead of it) rejects gets one repair attempt, never two.** `proposeGarment` (`lib/ai/index.ts`) feeds the specific defect back to the model and re-issues once, with a tighter per-call timeout so both attempts together stay under the transaction's 30s budget; a repeat failure propagates unchanged to the route's catch, which refunds exactly as a first-attempt failure would.
- **Prompt injection via an attached image's own text is not a new attack surface.** The prompt tells the model to treat text inside an image as content to describe, never an instruction — but **the actual defence is structural**: `applyGarmentSpec` drafts through `resolveMeasurements`, which clamps every measurement to `MEASUREMENT_RANGES` regardless of what the model claims prompted the value.
- Costs exactly `COSTS.adjust`, identical to a text-only message — one `propose_garment` call either way.
