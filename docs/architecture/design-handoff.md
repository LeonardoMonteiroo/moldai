# Design source of truth

> For the why behind these rules — the "reference, not a verdict" reversal on login's red error labels, and the full screenshot-audit history — see [`../decisions/design-handoff.md`](../decisions/design-handoff.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

`docs/design/` holds a redesign handoff: `README.md` (a screen-by-screen comparison against the current implementation) plus `screens/*.dc.html` (12 reference files — 11 one-per-screen plus `Estados de interacao.dc.html`, a sheet of hover/focus/pressed/disabled pairs for every interactive element) and `screenshots/*.png` (rendered captures, since the `.dc.html` files depend on an internal editor runtime and don't run standalone). `screenshots/states/<screen>/NN-nome.png` covers per-state captures (empty, loading, load-error, action-error, open dialogs, wizard steps, tabs, content variations) across all 11 screens. **Every screenshot is a confirmed 1280×900 capture** — desktop-only, no responsive/mobile coverage except the Editor's own explicit desktop-only state. It reuses the `moldai-ui` tokens already in `app/globals.css` rather than inventing a new visual language, so most of it is layout/spacing refinement to review component-by-component against the screenshots, not a content change.

**The handoff is a reference, not a verdict.** A `.dc.html` records what the designer drew; it does not outrank a product judgement about the screen it draws. Where the implementation is genuinely better, the implementation wins — and the divergence gets **recorded in the decisions file**, so the next screenshot-alignment pass reads it as a decision instead of drift and reverts it. **The bar is a stated reason, not taste.** Anchor: **the invalid-credentials state colours its field labels with `--color-alert`** — `Autenticacao.dc.html` leaves them at default ink and reddens only the input border and the message, which reads weaker than what the app does. Kept on purpose; **do not "fix" those labels back toward the design.**

**Two named exceptions to "the reference wins":** the marketing surface (`/`, `/planos`, `/privacy`, `/terms`) is a deliberate, documented divergence onto its own type system, not drift — see [`design-system.md`](design-system.md); and one real, unresolved architecture question: whether "Exportar" should open a **modal inside the editor** (what the handoff's newer screenshots document) or stay the dedicated `/pattern/[id]/export` screen (`ExportShell`, what's actually built) — see [`export.md`](export.md). Needs a decision before it's tracked as a gap either way.

**This is a different document from the original numbered-screen (`4a`/`4b`/`5d`/`5e`/`5i`, etc.) wireframe spec that was removed pending a redo** — the `design-Nx` ids still cited in older tickets and specs remain historical, unresolvable pointers into that still-retired document; don't try to chase them down.

**`scripts/design-review/` is the tooling for running a screenshot-alignment pass — not a test suite.** `run.mjs` drives one or more `scenarios/*.mjs`, each putting one screen into a real state (a genuine failed login, a genuinely pending request, a genuinely rate-limited account) via Playwright, then captures it next to its reference PNG. **The values it prints are reported, never enforced** — a difference is something to look at and decide about, which is the review conversation itself, not a pass/fail gate. It reaches Playwright via an absolute path into `.claude/skills/playwright-skill`'s own `node_modules` rather than a project dependency, and clears its Redis rate-limit buckets up front so a repeated run doesn't get throttled by its own previous pass. Run it with `node scripts/design-review/run.mjs <scenario>` (e.g. `login.invalid`, or bare for all scenarios); `REVIEW_URL`/`REVIEW_OUT`/`REVIEW_HEADLESS`/`REVIEW_HOLD` env vars steer it.
