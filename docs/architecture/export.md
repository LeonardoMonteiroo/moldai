# Export (client-side transform, no server call)

> For the why behind these rules — the offset/mitre math, the `foldEdge`-is-a-chord finding, the sheet-packing overlap bug, and every per-format decision — see [`../decisions/export.md`](../decisions/export.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- **`lib/export/` turns the drafted pattern into a downloadable file with no API route, credit cost, or state mutation.** `buildExportModel(pattern, t)` (`model.ts`) re-drafts in exact cm via `draftPiecesCm` — **it never reverses the store's px back to cm**, so it doesn't inherit `PX()` rounding. The `ExportModel` is format-agnostic: per-piece outlines as typed cm segments (`line`/`cubic`, Béziers preserved) plus grainline/dart/notches/name/qty.
- **Every piece carries two outlines: `outline` (the net sewing line) and `cutOutline` (the real cut boundary, `outline` offset outward by `seamAllowanceCm`).**
- **`offsetOutlineCm` (`offset.ts`) computes `cutOutline` with one rule that _is_ both required corner treatments at once**: flatten curved spans to a dense polyline, translate each fine segment outward, and rebuild each vertex as the intersection of its two adjacent offset lines — a convex corner's lines diverge past the original vertex (mitre), a concave one's cross before it (trim). No per-corner branching. **Outward direction is self-calibrated, never assumed from a fixed winding**: it builds both candidate polygons and keeps the larger-area one. `removeSelfCrossingLoops` repairs the one real limitation — a sharp reflex feature (a max-depth V-neck apex) can leave a self-crossing loop.
- **`foldEdge` is a chord, not a boundary edge.** It names two diametrically-opposite vertices on an already-whole, mirrored outline, because every current drafter joins both halves before attaching it — there is no literal edge to zero out. It doesn't need to fire: at a true axis-of-symmetry vertex the tangent is forced perpendicular by the mirror symmetry, so a uniform offset already keeps the point on the fold line.
- **#243: a piece's internal loops (holes) each get their own net/cut pair, `ExportInternalLoop` (`model.ts`), in the SAME local (shifted-to-net-bbox) frame as the piece's own `outline`/`cutOutline`.** `buildInternalLoop` calls `offsetOutlineCm(..., direction: "inward")` for a loop's cut line — the opposite of the outer boundary's own outward growth, since a hole's seam allowance folds fabric UNDER, into the opening, shrinking it rather than growing it. Every serializer draws a loop exactly the way it draws the outer boundary (same layer/pen: DXF/AAMA-DXF put it on the cut/net layers, `1`/`14` and `CONTORNO`/`COSTURA`, never the internal-marks layer `8`/`INTERNO`, since a hole is a real cut boundary, not a construction mark). No drafter emits one yet — future work; see [`drafting.md`](drafting.md).
- **A mitred convex corner can grow past a plain edge offset, and any packer must reserve for that or two pieces' cut lines touch.** `buildExportModel` computes each piece's `growLeft`/`growTop`/`growRight`/`growBottom` and packs by the effective footprint, offsetting `originCm` so the **cut line's** bbox lands on the shelf cursor. `planCutLayout` fixes the same exposure differently — re-zeroing each `CutInstance` to the cut line's own bbox up front, since a fresh instance shares no frame with a net outline.
- `exportPattern(pattern, format, t, onError?, size?, opts?)` builds the model, serializes, and downloads via `downloadFile` (`download.ts`, the only DOM touchpoint), dispatching all seven formats (`svg`/`dxf`/`dxf-aama`/`pdf-a4`/`pdf-single`/`pdf-layered`/`plt`) through an exhaustive `switch`/`never`. `opts: ExportRenderOptions` (`{pageSize?, rollWidthCm?}`) is optional and additive. The `Footer`'s menu is disabled when a conflict is active, the pattern is blank, or there is no `spec`.
- **Per format:**
  - `toSvg` — 1:1 in mm (`MM = 10`). Cut line solid and primary; net line a secondary dashed gray. Notches are short solid `#000` ticks (a notch is a cut mark, not a construction line).
  - `toDxf` — generic geometry-only, `$INSUNITS=4` mm, Y flipped, named layers `CONTORNO` (cut) / `COSTURA` (net) / `INTERNO` / `GRAINLINE` / `TEXTO` / `DOBRA` / `PIQUE`. Cubics flattened by adaptive De Casteljau at 0.2 mm.
  - `toDxfAama` — a **"compatível AAMA/ASTM D6673" subset**: numbered layers with fixed semantics (`1` cut boundary, `4` notches, `6` fold, `7` grainline, `8` internal/dart, `13` drill holes, `14` sew line), each piece in a `BLOCK`/`INSERT`, header R13 with classic `POLYLINE`/`VERTEX`/`SEQEND`. **Still tagged "beta" — because none of it has ever been opened in a real CAD importer**, only parsed back apart in this repo.
  - `toPdf` — 1:1 in four modes. `"a4"` tiles with page numbering and a 10 cm calibration ruler on sheet 1; `"single"` is one page the exact size of the sheet; `"roll"` is a single row of numbered strips up to `rollWidthCm` wide, overlapping by `STRIP_OVERLAP_CM`, its math in the shared `strips.ts` so PLT reports the same strip count. `PdfPageSize` (`"a4" | "a0" | "letter"`) parameterizes `"a4"` only. Loads `pdf-lib` via a dynamic `import()` inside `toPdf`, code-splitting it out of the main bundle.
  - `toPdfLayered` — one real **Optional Content Group per size** on a single sheet, plus a legend and the calibration ruler, redrafting one `ExportModel` per size in `baseSize` ∪ `sizesApplied`. Each size gets its own `LAYER_PALETTE` color. **The net sewing line and fold are deliberately not drawn at all** — `Footer.formatPdfLayeredNote` states that gap on the export menu itself.
  - `toPlt` — standard HPGL/2, `1016/2.54` units per cm. Distinguishable pens mirror the DXF layer split one-for-one; drill holes use HPGL/2's native `CI`. **Still badged "beta", the larger of the two uncertainties: never plotted on a physical device.**
- **The cm-accurate model is reused on-screen too.** `buildPathD` is the shared outline→`d` builder for `toSvg` and the React previews. `planCutLayout` (`cutplan.ts`) computes a real nesting — expanding each piece by cut quantity and packing copies into a selectable fabric-width strip, grain locked, no rotation — and **nests the cut line, not the net line**, so a larger seam allowance legitimately consumes more length. Backs `CutPlanTab` and `TechSheetTab`.
- **`planCutLayout` exposes two `NESTING_MODES`, both nesting each copy's _bounding box_, not its outline** — true no-fit-polygon nesting is out of scope and `CutPlanTab.layoutNoteAuto` says so. `"auto"` is the best of two pure packers (shelf and bottom-left skyline), never worse than shelf by construction. `"manual"` starts from the auto placement and overwrites named origins, clamped inside the fabric width; `overlappingInstanceIds` **flags but never auto-corrects** an overlap. No rotation is offered at all. Placements live in `useEditorStore`, cleared on the same version-change reset that clears `measurements`, and **do not survive a reload**.
- **`planCutLayout`'s `opts.cutQuantities` (`Partial<Record<SizeLabel, number>>`) nests multiple sizes' garments together** (#280) — `undefined` is the pre-#280 default (baseSize only, at each piece's own drafted `qty`); once defined, it's the sole spec — a size missing from it, or at 0, nests nothing for that size, baseSize included, and one `buildExportModel(pattern, t, size)` pass runs per size with a quantity > 0, its instances repeated and id-prefixed by size so they stay unique once concatenated. Unlike `fabricWidthCm`/`cutPlacements`/`nestingMode` above, this **does survive a reload**: it's `Pattern.cutQuantities`, a real (additive, optional) field on the persisted blob, written through `PATCH /api/patterns/[id]/cut-plan` and re-validated on every write by `validateCutQuantities` (`lib/export/cutQuantities.ts`) against the drop-unknown/clamp-out-of-range/never-throw contract, clamped per-size to `MAX_CUT_QUANTITY_PER_SIZE` and in total to `MAX_TOTAL_CUT_QUANTITY` (`lib/types.ts`) since the packer's cost scales with the combined instance count. `CutPlanSizePanel.tsx` is the "Quantidade por tamanho" UI, docked as its own 250px column in `CutPlanTab`, alongside a "Tecido" section (fabric-width presets + a real ±5cm stepper, `[90,200]`) and the real auto/manual toggle.
- **`CutPlanPreview`'s `<svg>` renders at a fixed, real px-per-cm scale (`SCALE_PX_PER_CM = 3.2`, `Editor.dc.html`'s own `corteScale`), not a responsive `w-full h-auto` capped by a `maxHeight`.** The earlier responsive approach scaled the WHOLE drawing down to keep fitting under the cap as more sizes/quantities nested taller, so a large plan just got smaller and smaller instead of the card scrolling to it. A fixed scale keeps every piece legible at a constant real-world size regardless of plan height; `CutPlanTab`'s wrapping card (`overflow-auto`) is what scrolls, both axes, once the plan's real pixel size exceeds it.
- **`/pattern/[id]/export` is a dedicated screen**, distinct from the editor footer's menu — `ExportShell` through `AppShell`. Lists every real `EXPORT_FORMATS` entry plus the unbuilt ones disabled and badged; an options panel whose unbacked controls are **honestly disabled with a stated reason** while page-size/roll-width are real and format-conditional; and a checklist (conflicts, closed-piece count, fabric consumption) that **blocks** the download while a conflict is active.
- **`User.exportPreset Json?` is one preset per account** — not per pattern, not multiple named presets. `GET`/`PUT /api/account/export-preset` round-trip it, and `lib/db/exportPreset.ts` **re-validates on every read and write** through `validateExportPreset` (drop-unknown/clamp-out-of-range/never-throw, the `validateSizeChartPatch` contract — see [`size-charts.md`](size-charts.md)). `PUT` deliberately stays on `readJsonObject`, not `parseBody` — the validator already owns the whole trust boundary. **`localStorage` was dropped, not kept as a fallback:** a per-browser cache of an account-level fact is the same duplicated-fact mistake as `Wallet.planLabel`.
