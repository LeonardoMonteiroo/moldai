# Conventions: language, copy, and product-visible honesty

> For the why behind these rules, see [`../decisions/conventions.md`](../decisions/conventions.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- **Commits:** always English, [Conventional Commits](https://www.conventionalcommits.org/) — `type(scope): summary` (e.g. `feat(i18n): add pt-BR catalog`). Types: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `ci`, `style`.
- **Language boundary:** code identifiers, wire keys, enum values, Prisma models/columns, and routes are **English**; UI display text is **pt-BR**; the AI's chat replies mirror the user's own language. Full-page screen routes are English, with `/planos` the one deliberate marketing exception — the footer's legal pages are `/privacy` and `/terms` rather than pt-BR, so that exception stays at exactly one.
- **Translate domain terms from the pt-BR design doc, don't transliterate them:** "grades" → `SizeChart` (not `Grade`), "molde" → `Pattern` (not `Molde`). **Get it right up front** — and note the expensive kind of change is a _wire-shape_ change, not an identifier rename: the earlier PT→EN rename of the persisted `EditorState`'s keys/values wiped every persisted pattern blob.
- **UI labels come from catalog lookups keyed by the EN enum value** — e.g. `t("garmentType." + spec.type)` — never a hand-written `Record<Enum, string>` label map.
- **Display-copy tone is governed by the vendored `humanizer` skill** (`.claude/skills/humanizer/`, MIT, pinned in `skills-lock.json` by source + sha256) — run it whenever catalog copy is written or revised. **Never hand-edit its `SKILL.md`**: re-pull upstream and re-hash, the same rule the `shadcn` skill follows. Three constraints it does not encode itself: **the register stays formal** (never add first person, jokes, exclamation marks or opinion — this product talks to working pattern-makers); **its overused-word lists are English and do not fire on pt-BR at all**, so only its language-agnostic structural rules carry a pass here, with the pt-BR tells ("vale ressaltar", "no cenário atual") judged by ear; and **its blanket no-em-dash rule is a judgement call, not a mechanical strip** — the catalog's `—` include a genuine repeated tell, but its middle dots (`·`) are a deliberate UI separator the skill has no opinion about. A pass rewrites **values only** — a key, ICU placeholder, plural form or embedded markup is never touched, or the rewrite becomes a call-site change.
- **The core flow has to be audible, not just visible.** `ChatPanel`'s thread is `role="log"` + `aria-live="polite"` (`log`, not a bare `aria-live`, so only the new turn is read rather than the whole history). **`GeneratingOverlay` is `role="status"` and the _single_ live region for progress** — `ChatPanel` renders the same step text and is deliberately left silent, or every step would be announced twice. Each screen's loading state is `role="status"` and its load error `role="alert"`.
- **Surface feature limitations on-screen, never silently.** A scope boundary, unsupported case, or mock standing in for the real thing must be explicit where the user meets it (inline note, disabled control with a reason, badge) rather than failing, no-op'ing, or pretending completeness. Mark planned capabilities **"em breve"** so they're distinguishable from hard limitations, and **prefer showing an option disabled+badged over hiding it**. Anchors: `Proof3DTab`'s own `notSupportedFor.{hoodie,coat,shirt}` (the three archetypes only the `freesewing` engine drafts — see [`drafting.md`](drafting.md)'s `#254` entry, which closed the same tab's earlier trousers gap); `Footer.formatPdfLayeredNote`; the AAMA/ASTM DXF export tagged "beta" with its remaining gap noted inline.
- **Don't add abstractions beyond what's needed** — `/settings` and `/pattern/[id]/versions` deliberately have no Zustand store: no cross-component shared state, and section choice lives in the URL. This rule has exactly one documented, deliberate exception today: the swappable drafting engine (see [`drafting.md`](drafting.md)). No second engine is registered — the exception is not "we might swap engines one day," which is precisely the speculative argument this rule exists to refuse. It is justified by three concrete, already-realized capabilities: `tshirtBenchmark.test.ts` can score any registered engine in-repo instead of a throwaway project outside it, a stated `EngineCapability` contract makes a drafter's own gaps reportable instead of implicitly defaulted, and a pattern can freeze which engine drafted it without a second engine existing yet.
