# Observability

> For the why behind these rules, see [`../decisions/observability.md`](../decisions/observability.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- **`lib/observability/report.ts`'s `reportError(scope, err, context?)` is the one seam between "logged to stdout" and a real error-reporting service** — it wraps `console.error` today, so wiring in a real reporter later is an edit to this one file, not a sweep across every catch block that calls it. It's called from the AI generation flow's catch at `app/api/patterns/[id]/generate/route.ts` (with `patternId`/`userId` context), from `app/error.tsx`/`app/global-error.tsx`'s boundaries, and from `scripts/cron-renew.ts`'s failure path.
- **`GET /api/health`** (unauthenticated, see [`api-routes.md`](api-routes.md)) gives the Docker/Compose healthcheck something to probe — Postgres (`SELECT 1`) is a hard dependency and its failure answers 503; Redis (`PING`) is reported in the body (`redis: "ok" | "unreachable"`) but never fails the check, since the rate limiter already fails open by design rather than treating a Redis blip as the app being down (see [`rate-limiting.md`](rate-limiting.md)).
- **`lib/security/headers.ts`'s `SECURITY_HEADERS` is pure data** so the `node` vitest suite (which covers `lib/**`/`app/**`, not `next.config.ts`) can assert against the header list; `next.config.ts` just spreads it over `source: "/(.*)"`. Four ship today: `Strict-Transport-Security` (2 years, `includeSubDomains`), `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, alongside `poweredByHeader: false`. **A Content-Security-Policy is deliberately absent, not forgotten** — Next's inline bootstrap script needs a nonce and a naive policy would break the app; `X-Frame-Options` is the interim clickjacking mitigation for `/login`'s credentials form that CSP's `frame-ancestors` would otherwise supersede.
