# Observability

> For the why behind these rules, see [`../decisions/observability.md`](../decisions/observability.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- **`lib/observability/report.ts`'s `reportError(scope, err, context?)` is the one seam between "logged to stdout" and a real error-reporting service** — it still writes to stdout unchanged, and (#275) also forwards to Sentry via `lib/observability/sentry.ts`, so wiring in a real reporter was an edit to two small files, not a sweep across every catch block that calls it. It now has roughly 30 production call sites across `app/`, `lib/db/`, `lib/draft/`, `lib/observability/langfuse.ts` and `scripts/` — no longer just three, and still growing; grep `reportError(` rather than trusting a count here to stay current.
- **Sentry is wired from the existing `register()` hook (`instrumentation.ts`) and a new `instrumentation-client.ts`, both driven by `lib/observability/sentry.ts`.** `NEXT_PUBLIC_SENTRY_DSN` is the one config knob — unset is a silent no-op in every environment, matching the `LLM_*`/`REDIS_URL` pattern in `lib/schemas/env.ts`; `npm run build` passes with no DSN, same as before. One DSN var serves both the server and browser SDKs (a DSN isn't a secret, so a second copy would just duplicate the fact) — see [`decisions/observability.md`](../decisions/observability.md) for why. `instrumentation.ts` also exports `onRequestError` so server errors Next catches outside the `reportError` seam are reported too.
- **Errors only — no performance tracing, no Session Replay.** `tracesSampleRate: 0`. Replay records the DOM, which would ship chat message bodies and generated pattern images to Sentry; staying errors-only also keeps volume inside the free Developer tier.
- **Context is redacted before it leaves the process.** `forwardToSentry`'s `redactContext` (`lib/observability/sentry.ts`) replaces any context value whose key looks like it could hold personal data or generated content (`email`, `token`, `password`, `message`, `image`, …) with `"[redacted]"` before the Sentry payload is built — stdout keeps the original object. This is what lets `app/api/password-reset/request/route.ts`'s `reportError(..., { email })` stay untouched: the operator's log line still has the address, Sentry never sees it.
- **A future CSP owes `connect-src` a Sentry ingest-domain entry.** There is no CSP yet (see below), so nothing blocks the browser SDK's requests today — but whoever writes one must allowlist Sentry's ingest origin or client-side error reporting silently stops.
- **`lib/observability/langfuse.ts`'s `traceProposeGarment` (#276) traces every `lib/ai/` provider call** — model, provider, token usage, latency, whether the repair retry fired, and `validateSpec`'s substitutions/clamps (#250). Same shape as `sentry.ts`: `"langfuse"` is only ever dynamically imported, gated behind `LANGFUSE_SECRET_KEY`/`LANGFUSE_PUBLIC_KEY`, both optional and unset by default — an unconfigured environment never loads the SDK. Fire-and-forget by construction, called from `lib/ai/index.ts`'s `proposeGarment`, never awaited, so it adds no delay inside `withPatternAndWallet`'s transaction. Prompt/response bodies are gated a second time behind `LANGFUSE_TRACE_CONTENT=true` (LGPD opt-in, off by default) — see [`ai-provider.md`](ai-provider.md) for the full contract.
- **`GET /api/health`** (unauthenticated, see [`api-routes.md`](api-routes.md)) gives the Docker/Compose healthcheck something to probe — Postgres (`SELECT 1`) is a hard dependency and its failure answers 503; Redis (`PING`) is reported in the body (`redis: "ok" | "unreachable"`) but never fails the check, since the rate limiter already fails open by design rather than treating a Redis blip as the app being down (see [`rate-limiting.md`](rate-limiting.md)).
- **`lib/security/headers.ts`'s `SECURITY_HEADERS` is pure data** so the `node` vitest suite (which covers `lib/**`/`app/**`, not `next.config.ts`) can assert against the header list; `next.config.ts` just spreads it over `source: "/(.*)"`. Four ship today: `Strict-Transport-Security` (2 years, `includeSubDomains`), `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, alongside `poweredByHeader: false`. **A Content-Security-Policy is deliberately absent, not forgotten** — Next's inline bootstrap script needs a nonce and a naive policy would break the app; `X-Frame-Options` is the interim clickjacking mitigation for `/login`'s credentials form that CSP's `frame-ancestors` would otherwise supersede.
