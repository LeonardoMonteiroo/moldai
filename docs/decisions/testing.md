# Testing conventions

> This is the _why_. For the operative rule, see [`../architecture/testing.md`](../architecture/testing.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- **`next-intl` does not throw on a missing key — it renders the literal key path, logs `IntlError: MISSING_MESSAGE`, and the test still passes.** This was verified empirically, not assumed: a test written against a substring, a regex, or the key name itself will pass whether or not the catalog actually resolves — which is precisely why the rule is "assert against the exported `ptBR` catalog object," not "assert some plausible-looking text is present." A test suite that looks green can still be blind to every catalog key silently failing to resolve.
- **`vi.mock` specifier mismatches are silent, which is what makes them dangerous.** If a test mocks `"@/lib/db/prisma"` but the subject module imports `"./prisma"` and the two don't independently resolve to the same absolute path, the mock simply never intercepts — the real dependency runs, and the test's own assertions report zero calls instead of throwing an error. There is no exception, no red test pointing at the mismatch; the test that should have caught a regression just quietly stops testing anything. `lib/db/aliasResolution.test.ts` exists as a standing regression guard specifically because this collapse (alias path vs. relative path resolving to different things) happened once and left a real defect uncaught.
- **#330: `spaceSampling.test.ts`'s seam-closure gate needed a carve-out that PROVES itself on every sample, not one that merely names a field and trusts it.** `STYLE_LIMITS.armholeDeepenCm` is `{min:0,max:6}` sampled uniformly, and a deepen with no refit makes `armhole-cap` diverge by design (the cap is sized from the base armhole, never the deepened one). But `armholeDeepenCm > 0` alone is a near-vacuous guard — the uniform draw is essentially never exactly 0 — so a gate that tolerated any divergence merely co-occurring with a nonzero deepen would silently pass a real, unrelated seam defect too, as long as SOME sampled field happened to be nonzero. The shipped carve-out instead re-drafts a **twin spec** with `armholeDeepenCm` zeroed and checks, in order: the divergent set is exactly `{armhole-cap}`; `subSegmentDiffCm` stays within tolerance (a deepen moves front and back equally, so it can never legitimately skew the split); the twin closes on its own; the twin's own cap length is byte-identical to the original (the cap is sized off the base armhole — deepening the body must not move it at all); and `diffCm` sits within one tolerance of the twin-vs-original armhole growth exactly (no fudge factor: with `gatherRatio=1`, `diffCm = |bLen − aLen − ease|`, so a closing twin plus an unmoved cap pins `diffCm` to within tolerance of that one measured number). Verified against the real drafting matrix before shipping: `armholeDeepenCm` diverges the pair starting around 0.55cm, `diffCm ≈ 1.9×deepen` at 1cm rising to `≈11.3` at the 6cm ceiling, `subSegmentDiffCm` staying `0` throughout every measured value. **Never loosen this by trusting the field's presence alone** — the whole point is that the carve-out fails the moment a divergence isn't explainable by the deepen amount, catching a compound regression (a real defect landing alongside a legitimate deepen) that a name-only guard would wave through.
- **A gate's allowlist must be proven closed, not just declared.** #330's orphan-piece gate (every drafted piece must be named by some declared seam pair) ships with exactly one exception, `placket` — cited from `lib/draft/subpieces.ts`'s own doc on why it has no mating edge to declare, never a second copy of that reason. Before trusting it, the allowlist itself was emptied and the gate re-run to confirm `orphanPiece` actually goes red (21/250 maxCorner samples failed, all `placket`) — the same "run it, don't assume it" discipline applies to a carve-out or an allowlist as it does to the gate it's carved out of.
