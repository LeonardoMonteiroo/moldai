# i18n (`next-intl`, single-locale pt-BR, no routing)

> This is the _why_. For the operative rule, see [`../architecture/i18n.md`](../architecture/i18n.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

- **Every display-text screen was a client component until `app/verify/page.tsx`** — the project's first server component with display text, using `await getTranslations(...)` directly; its interactive part, `components/auth/VerifyCard.tsx`, is still a client component reading the same `Verify` namespace via `useTranslations`. `/login` and `/signup` followed the same split under #109, so `generateMetadata` could set each route's tab title: `app/login/page.tsx`/`app/signup/page.tsx` are now the server-component shells rendering the static heading, and `components/auth/LoginCard.tsx`/`SignupCard.tsx` hold the interactive form. This history matters because it explains why most of the app is still one shape (client component reading its own namespace) while a handful of auth screens are a different shape (server shell + client form) — it's not an inconsistency, it's the sequence in which the split was introduced.
- **The `Translate` seam was shipped as "i18n Fase 2"** — a deliberate phasing, not a partial implementation left unfinished. Phase 1 was next-intl wired into components; Phase 2 was threading an injected resolver through every framework-free `lib/` function that produces display text, so `lib/` never gains a `next-intl` import.
- **Drafters emit the resolved string, not the key, so the persisted blob shape is unchanged — no reset migration was needed.** This is the same "cheap direction of a blob change" reasoning as `Pattern.savedAgo` (see [`data-layer.md`](data-layer.md)): because the persisted value is already a plain string either way, switching where that string comes from (hardcoded → catalog lookup) doesn't change what's stored.
- **`apiError`'s internal `STATUS_WORD` map reproduces each response's pre-existing wire `status` discriminator, warts included**: `/api/account/*` answers its 404 with `status: "error"`, not `"not_found"`. This was preserved rather than normalized specifically because normalizing it would be a wire-shape change reaching every existing client call site that pattern-matches on that literal string — the same category of expensive change the language-boundary convention warns about.
