# Conventions

> This is the _why_. For the operative rule, see [`../architecture/conventions.md`](../architecture/conventions.md).
> For universal, cross-cutting rules, see the root [`CLAUDE.md`](../../CLAUDE.md).

> **Note (this pass):** the text below predates later changes and is now stale in at least four places: `text-hero` is 54px today (not 44), there are 10 raw `<button>` exceptions today (not 9), there are two deliberate sidebar widths today (200px nav, 172px settings — not one 186px average), and the editor's header now persists through every pre-ready state rather than early-returning full-screen. See `docs/architecture/conventions.md` and `docs/architecture/design-system.md` for the current rules.

## Conventions

- **Commits:** always English, [Conventional Commits](https://www.conventionalcommits.org/) — `type(scope): summary` (e.g. `feat(i18n): add pt-BR catalog`, `fix(export): clamp dxf tolerance`). Common types: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `ci`, `style`.
- **Language boundary:** code identifiers, wire keys, enum values, Prisma models/columns, and routes are **English**; UI display text is **pt-BR**; the AI's chat replies mirror the user's own language (see i18n below). Full-page screen routes are English — `/pattern/[id]`, `/settings`, `/size-charts` (the first two were renamed from `/molde/[id]`/`/configuracoes`, along with `Molde`→`Pattern` and `/api/moldes/*`→`/api/patterns/*`).
- **Translate domain terms from the pt-BR design doc, don't transliterate them:** "grades" → `SizeChart` (not `Grade`), "molde" → `Pattern` (not `Molde`). Both were shipped transliterated first and each cost a repo-wide rename sweep — files, functions, routes, Prisma models/columns, i18n keys, plus a migration apiece (`rename_molde_to_pattern`, `rename_grade_to_size_chart`). Get it right up front. (Separately, the earlier general PT→EN rename of the persisted `EditorState`'s keys/values changed the stored JSON shape and required `reset_moldes_english`, which wiped every persisted pattern blob — a wire-shape change, not just an identifier rename, is the expensive kind.)
- **UI labels come from catalog lookups keyed by the EN enum value** — e.g. `t("garmentType." + spec.type)` in `TechSheetTab`, the `PatternData` namespace's `neckline.*`/`skirtSilhouette.*`/`sleeveType.*` keys resolved inside the drafters — never hand-written `Record<Enum, string>` label maps.
- **Display-copy tone is governed by the `humanizer` skill at `.claude/skills/humanizer/`** (pinned in `skills-lock.json`, vendored verbatim from `blader/humanizer`, MIT — never hand-edit the `SKILL.md`; re-pull upstream and re-hash instead, the same rule the `shadcn` skill follows). It is 35 named AI-writing tells drawn from Wikipedia's "Signs of AI writing" — inflated importance, sales language, forced triads, `not X but Y`, section scaffolding, generic positive endings — and it is the tool to run over `messages/pt-BR.json` whenever copy is written or revised (issue #202 is the standing sweep of the existing catalog). Three project-specific constraints the skill itself does not encode: **(1) the register stays formal.** The skill's own "Add personality only when it fits" branch says to keep reference and technical text neutral, and that is the branch this product takes — a humanizing pass may never add first person, jokes, exclamation marks, or opinion to a tool that talks to working pattern-makers. **(2) Its word lists are English, its structure rules are not.** §7 (overused AI words), §8 (`serves as`/`boasts`), §9 and §32 are English lexical lists that do not fire on pt-BR at all; the structural patterns (§1–6, §10–18, §20–35) are language-agnostic and are what actually carry a pass over this catalog, with the pt-BR equivalents ("vale ressaltar", "no cenário atual", "mergulhar", "de forma eficiente") judged by ear rather than by list. **(3) §14's blanket no-em-dash rule is a decision here, not a mechanical strip** — the catalog holds 53 `—`, and while the uniform " — trailing explanatory clause" shape is a genuine tell worth thinning, the middle dot `·` (86 occurrences, e.g. `"há 2 min · v3"`) is a deliberate UI separator and not punctuation the skill has any opinion about. In every case the pass rewrites **values only**: a key, an ICU placeholder (`{plan}`, `{size}`), a plural/select form or embedded markup is never touched, or the rewrite becomes a call-site change. The skill governs display text — CLAUDE.md, commit messages and the English system prompt in `lib/ai/prompt.ts` are out of its scope. `.claude/` is in `.prettierignore`, so the vendored `SKILL.md` stays byte-identical to upstream and the pinned hash keeps meaning something.
- **The core flow has to be audible, not just visible.** Before this fix, live regions already existed off the critical path — a field's validation error, a load-error banner, a size-chart cell's range hint — but none of them sat where the user actually spends the session: you sent a chat request and the AI's reply appeared announcing nothing, and the multi-step generation progress changed announcing nothing. `ChatPanel`'s thread is `role="log"` + `aria-live="polite"` (`log`, not a bare `aria-live`, so only the new turn is read rather than the whole history); `GeneratingOverlay` is `role="status"` and is the **single** live region for progress — `ChatPanel` renders the same step text in its composer and is deliberately left silent, or every step would be announced twice; each screen's loading state is `role="status"` and its load error `role="alert"`.
- **Surface feature limitations on-screen, never silently.** A scope boundary, unsupported case, or mock standing in for the real thing must be explicit where the user meets it (inline note, disabled control with a reason, badge) rather than failing, no-op'ing, or pretending completeness. Mark planned/feasible-later capabilities **"em breve"** so they're distinguishable from hard limitations, and prefer showing an option disabled+badged over hiding it. Anchors: the `Prova 3D` tab's own hoodie/coat/shirt gap (`Proof3DTab`'s `notSupportedFor.{hoodie,coat,shirt}`, e.g. "a prova 3D ainda não cobre moletom com capuz — em breve" — a named, distinct state, not the ordinary "generate a pattern first" empty state and not the tab hidden or claimed unavailable, since the tab shipped in #165/#10; #254 later closed this same tab's original trousers instance of the gap once `lib/proof3d/mesh.ts` learned to build a real shell for that archetype, per [`drafting.md`](drafting.md)'s own `#254` entry); the `pdf-layered` export's own on-screen note (`Footer.formatPdfLayeredNote`) that it deliberately omits the net sewing line and fold to keep the per-size overlay legible; the AAMA/ASTM DXF export tagged "beta" with its remaining gap (never opened in a real CAD importer) noted inline.
- **Design tokens live in `app/globals.css`** as Tailwind v4 `@theme` variables (colors, radius, shadow scale) — this project has no `tailwind.config.ts`. Fonts (Bricolage Grotesque for display/titles, Archivo for UI/body) load via `next/font/google` in `app/layout.tsx`, exposed as CSS variables. Extend the `@theme` block; never hardcode hex values in components. One token deliberately diverges from the handoff: `--color-muted` was darkened from `#8b8779` to `#6e6b60` because the original sat at 3.2–3.6:1 and failed WCAG AA on every ground it is used against; `#6e6b60` clears 4.5:1 on white, surface-alt, paper, olive-tint and amber-bg, and stays lighter than `--color-muted-2` so the two-level text hierarchy survives.
- **shadcn/ui is installed, but the MoldAI tokens stay the source of truth.** `components.json` (hand-written — never run `shadcn init`: it overwrites the `@theme` block with its own oklch palette), `components/ui/`, `lib/utils.ts`'s `cn()`, and the version-pinned `shadcn` MCP server in `.mcp.json`. shadcn's semantic names (`--color-primary`, `--color-background`, `--radius-md`, …) exist only as a **second `@theme inline` block aliasing the MoldAI tokens above** — never give one a literal value. `--color-border` and `--color-muted` are deliberately **not** aliased: they are MoldAI tokens with ~90/~105 existing call sites, and shadcn means a _surface_ by "muted" where this repo means _text_ — so a ported component's `bg-muted` becomes `bg-surface-alt`, while `text-muted-foreground` maps through and works as-is. The app is light-only: `@custom-variant dark (&:is(.dark *))` keeps the `dark:` classes shadcn ships inert (without it, Tailwind v4 fires them on `prefers-color-scheme` and a dark-OS visitor gets half-dark controls on a light page). Every screen consumes these primitives now; raw `<button>` is down to 9 deliberate exceptions, every one a clickable _region_ or an ARIA-role-bearing option rather than a control: the pattern thumbnail surface, the two paywall plan cards, the multi-line size-chart rows, `ImportSizeChartDialog`'s dashed trigger card, and `OnboardingShell`'s four (a `role="radio"` work-style option, the multi-line default-chart card, and two disabled+badged "em breve" rows). Tune a primitive in `components/ui/`, never with per-call-site `className` overrides: that is where the extra `Button` sizes/variants (`chrome`, `accent`, `soft`, `destructiveOutline`), `Badge`'s `size="chip"` and `soon`, and the `text-sm`→`text-ui`/`text-control` retuning live. **The chat stream is `bubble` + `marker`,** whose variants are the design's own: `default` (olive, the user's turn), `paper` (the AI's), `notice` (amber — a seam conflict, a failed generation, or a size-chart substitution; deliberately not `destructive`, which is the red alert token), `surface` (white, for a bubble holding controls rather than prose — the clarifying-question card). `ChatMessage.tone` carries `"notice"` alongside `"conflict"`: both render the amber bubble, but they stay distinct in the data model because an informational caveat is not a seam conflict. `components/ui/textarea.tsx` was added via `shadcn add` for the chat composer and retuned like the rest — its stock `text-base`/`md:text-sm` replaced by `input.tsx`'s `text-body`/`md:text-control` pair. The 3px corner in `BubbleContent` is the bubble's tail, not a `--radius-*` step. Three sibling registry items were considered and skipped: `message` (pure align/avatar/header scaffolding this chat has no use for), `attachment` (a full upload-lifecycle card; MoldAI's own photo/sketch chips send straight to the AI with no persisted upload at all — see Generation flow's #18 note — and the one remaining disabled `.dxf` pill doesn't need it either), and `message-scroller` (a new `@shadcn/react` runtime dependency that injects CSS into `app/globals.css`, overwrites `button.tsx`, and virtualizes a list holding a handful of messages — its one real benefit, not yanking a reader who scrolled up, is ~10 lines in `ChatPanel` instead). **`ScrollArea` carries two local additions, both forced by Radix:** `viewportRef` (the scrolling element is the viewport, not the Root — `ChatPanel`'s scroll-to-bottom has to target it) and `fill` (Radix wraps content in an inline-styled `display:table` box, which has no definite height and so collapses a `flex-1` child; `fill` swaps in a block box at the viewport's height and the call site adds `min-h-full` — needed by `CutPlanTab`'s empty state and `SizeChartsShell`'s two full-height columns; `PatternGrid` deliberately does **not** use it (#114) — its own `ScrollArea` was removed, and `DashboardShell` now wraps the grid together with the summary cards in one plain, non-`fill` scroll region, so an empty or lightly-populated grid takes its natural height instead of stretching to fill the viewport and shoving the cards to the floor). Its scrollbar defaults to `type="auto"`, visible exactly while the content overflows like the native bar it replaces, and its thumb is `bg-muted` rather than shadcn's `bg-border`: #ded9cc reads 1.26:1 on paper, so a hand-drawn thumb in it would be invisible where the native one was not, and a draggable thumb owes WCAG 1.4.11's 3:1. After any `shadcn add`: review the `app/globals.css` diff (`cssVariables: true` lets the CLI inject into it) and run `npm run format`, since the CLI's output doesn't match this repo's prettier config. `components.json` carries no `registries` map on purpose: `@shadcn` is built-in and its real URL holds an internal `{style}` placeholder, so hand-writing it would shadow the built-in with a broken one — pass `registries: ["@shadcn"]` explicitly to the MCP's search/list tools instead. The `shadcn` skill is installed at `.claude/skills/shadcn/` (pinned in `skills-lock.json`); it will suggest `shadcn apply <preset>` / `init --preset`, which **overwrite CSS variables and components** — never run either here, they would wipe the alias layer.
- **Type comes from the named scale, never `text-[Npx]`.** `app/globals.css` defines 8 steps as `--text-*` tokens — `text-tick` (10.5px) · `text-meta` (11.5) · `text-ui` (12.5, the default UI size) · `text-control` (13.5, buttons/inputs/tabs) · `text-body` (16) · `text-title` (21) · `text-display` (26) · `text-hero` (44, the landing hero's own step, `LandingHero` its only user) — each set to the dominant member of a measured cluster, collapsing the 259 ad-hoc `text-[Npx]` values that had drifted across 19 near-duplicate sizes (11/11.5, 12/12.5, 13/13.5). Uppercase labels take `tracking-eyebrow` (`0.08em`, so the tracking follows the step it is set at instead of pinning one absolute value across three sizes) — one named value for the 3 ad-hoc positive trackings that had drifted apart (`.8px`, `.6px`, `.5px`); the wordmark's display tightening is `tracking-wordmark` (`-0.4px`) and the landing hero's is `tracking-hero` (`-1.4px`), each named after its only user. Body text is `font-normal` — `font-semibold` had spread to 85 call sites and stopped meaning emphasis. **The sweep is finished, and staying at zero is the rule, not an aspiration:** `app/` and `components/` hold no `text-[Npx]` and no bracketed tracking, and the shadcn primitives carry no stock Tailwind size either (`text-sm`/`xs`/`base`/`lg` → `text-control` for controls, `text-ui` for secondary copy, `text-meta` for small print, `text-body` for headings), because a 14px shadcn default is out of scale against a 12.5px UI. A glyph used as an icon is sized as an icon (lucide + `size-*`, or `EmptyMedia`), never priced on the type scale — the `◍` at 28px in the `Prova 3D` empty state was the last of those.
- **Every full-page screen renders through `components/shared/AppShell.tsx`**, with one deliberate exception: `/login`, `/signup` and `/verify` are centered-card screens with no header, so they render their own `Wordmark` directly instead of going through `AppShell`. For every other screen, `AppShell` owns the page frame (header row, optional sidebar slot, content region as a flex column, optional footer slot) and builds `components/shared/PageHeader.tsx` itself from plain data props, so a screen cannot hand-roll a header. `PageHeader` is the one header: wordmark (`components/shared/Wordmark.tsx`, also used by the three centered-card auth screens above), optional `← Voltar`, title/subtitle, credits bar, "Comprar créditos", and an avatar dropdown carrying the `/settings` deep links plus sign out. Three props are deliberately optional, all three because of the dashboard: `backHref` (it **is** `/`, so a back button would point at the screen you are on); `title` (its sidebar already marks "Meus moldes" active, so a header title printed the same words twice — and with neither `backHref` nor `title` the wordmark's trailing `Separator` is suppressed too, or it would dangle against the empty spacer); and `credits`, which is nullable because the dashboard's balance arrives after first paint — the bar and "Comprar créditos" are simply absent until it lands, instead of the header flickering in. That last one is honestly named "transient" only on the happy path: if `GET /api/account/summary` fails, `credits` stays null for good and the content region's error message is what keeps the missing bar from being silent. There is **no global nav sidebar**; `sidebar` is whatever column the screen owns (`dashboard/Sidebar`, `SettingsSidebar`), and the editor and `/size-charts` pass none. `AppShell` itself renders `{sidebar}` bare — the 186px width (`w-[186px] border-r bg-surface p-[14px]`) is each sidebar component's own chrome, not a slot `AppShell` sizes, so a new sidebar-bearing screen must set that width itself. A screen whose body is a row (the editor: chat + canvas) passes one child that is itself a row. The editor is also the one screen that keeps a full-screen loading early-return rather than putting it in the content region, because the header's title _is_ the pattern name.
- **A display name that reaches a layout needs a cap _and_ a truncation.** `MAX_PATTERN_NAME_LENGTH` (`lib/types.ts`, beside `COSTS`) is enforced by `PATCH /api/patterns/[id]` and reused as the rename dialog's `maxLength`, so the field stops you before the round trip does. The API had accepted a 5000-character name, and neither `PageHeader`'s title nor `PatternCard`'s name truncated — the tell was that `lib/account/settings.ts` already capped the _user's_ name at 80 while a pattern's was unbounded. Both now `truncate` with `min-w-0` on the flex column; without `min-w-0` there is nothing for `truncate` to shrink against and the overflow just shoves its siblings (the credits bar and avatar off the header, the "⋯" menu off the tile).
- **A control must not rewrite what you typed.** `SizeChartTable`'s cells displayed `resolveSizeChartSize`'s _clamped_ output and wrote every keystroke straight back with `Number(e.target.value)` — the round trip corrupted the input outright: clearing the bust cell and typing "96" stored **1406**, each digit appended to the clamped value the previous digit produced. (`Number("")` being `0` was the smaller face of it: clearing a cell rewrote 92 to the range minimum.) `MeasurementCell` holds the in-progress text locally and commits only on blur/Enter, only when it parses and is in range; out-of-range or emptied gets `aria-invalid` plus a message naming the accepted range (lifted to the table — a 56px column has no room), and Escape restores. The progression-rule input is deliberately untouched: it is not clamped on display, so it has no feedback loop, and `0` is a meaningful rule value.
- **Don't add abstractions beyond what's needed** — e.g. `/settings` deliberately has no Zustand store: it has no cross-component shared state and section choice lives in the URL, so local `useState` per section is enough.
- **`.claude/hooks/check-conventions.mjs`'s hardcoded-pt-BR check (CHECK 1) and hex-color check (CHECK 2) scan `.tsx` **and `.ts`** files (each with its own `lib/` exemption list — `RAW_OUTPUT_TEXT_EXEMPT` for CHECK 1, the hex list for CHECK 2 — covering modules that bake text or color into an exported file rather than into the UI, e.g. `lib/export/{svg,dxf,dxf-aama}.ts`); its i18n key-existence check (CHECK 4) matches only a literal `t("…")` first argument** (it does not evaluate a template-built key like ``t(`plans.${plan}.name`)``, the `PageHeader` plan lookup above). The wire-error-codes sweep is the standing lesson on why a manual pass still matters: no single grep shape is a complete audit for display text — `lib/export/pdf.ts`'s tiled-page label was a backtick template and its calibration-ruler label opened on a digit, and `lib/sizeCharts/seed.ts`'s two system-chart names (since fixed — they now resolve from the catalog, see Size charts below) contained no accented character at all, so an accent-class pattern couldn't have seen them either. Three successive audit passes each found something the previous one missed.
- **Component tests are the `dom` vitest project** — jsdom + React Testing Library, configured in `vitest.workspace.ts` as a **second project** so the pure-logic `node` suite never loads the DOM setup file. `vitest.setup.ts` installs the jest-dom matchers, RTL auto-cleanup, and the browser APIs jsdom lacks that the Radix primitives call (`ResizeObserver`, pointer capture, `scrollIntoView`, `matchMedia`) — a Radix component that will not open in a test is almost always a missing one of those, not a broken assertion. Render through `renderWithIntl` (`components/test-utils.tsx`), which wraps the tree in the **real** `messages/pt-BR.json` rather than a stub translator — but next-intl does not throw on a missing key: it renders the literal key path (e.g. `"ProfileSection.errors.unauthorized"`), logs `IntlError: MISSING_MESSAGE` to the console, and **the test still passes**, verified empirically, not assumed. An assertion matching a substring, a regex, or the key name itself is therefore vacuous — it passes whether or not the catalog actually has the string — so catalog-text assertions must compare against the exact resolved `ptBR` value, never a pattern that a missing-key fallback could also satisfy. This is not hypothetical: an `unauthorized` catalog gap shipped mid-branch unnoticed and had to be fixed once a real assertion caught it. (The repo also has no next-intl typed-messages augmentation, so `t()` keys are checked statically in neither direction — not against the catalog, not against call sites.) For catalog-sourced display text — button labels, menu items, empty states, anything a component reads from `messages/pt-BR.json` — assert against the exported `ptBR` catalog object, never against a pasted pt-BR literal: the no-hardcoded-display-text rule applies to tests, and it makes a copy change a one-place edit. That rule governs assertions on catalog text, not test data: arbitrary strings passed in as fixture props (a pattern name, a garment label, a formatted subtitle like `AppShell.test.tsx`'s `"Configurações"` or `PageHeader.test.tsx`'s `"Meus moldes"`/`"Blusa"`/`"há 2 min · v3"`) are fine as plain literals, since they're test-supplied data rather than app-owned copy. (`.claude/hooks/check-conventions.mjs` already exempts `*.test.tsx` from the mechanical hardcoded-pt-BR check, so this written rule is the only thing governing the distinction.)
- **A `vi.mock(...)` call must use the exact specifier the subject module itself imports — never assume the `@/...` alias and a relative specifier for the same file are interchangeable inside a test.** `vitest.workspace.ts`'s `resolve.alias["@"]` is pinned to `path.resolve(__dirname, ".")` — this file's own directory, i.e. whatever checkout vitest is actually running from (a nested `.claude/worktrees/<name>/` git worktree, or the repo root) — and both projects also pin `root` to that same value (#166), so the alias and a relative import of the identical file are guaranteed to collapse into one module id. But a test doesn't get that guarantee for free just by using `@/...`: if the file under test imports its own dependency relatively (`lib/db/*.ts` importing `./prisma`, the prevailing style in `lib/db/`) and the test mocks it via the alias instead (`vi.mock("@/lib/db/prisma", ...)`), the two specifiers still have to independently resolve to the same absolute path for `vi.mock`'s interception to apply — and if that resolution is ever wrong (a misconfigured alias, a future refactor, an unusual invocation), the mismatch is **silent**: the mock simply never intercepts, and the subject's real dependency runs instead (in `lib/db/*.ts`'s case, a real, likely-unreachable `PrismaClient`) while the test's own assertions — reading the mock through its own, still-correctly-resolved alias import — report zero calls instead of a resolution error. `lib/db/users.test.ts` (#15) and the other `lib/db/*.test.ts` files (#166) all mock `"./prisma"`, matching `lib/db/*.ts`'s own specifier exactly, rather than `"@/lib/db/prisma"`; `lib/db/aliasResolution.test.ts` is a standing regression guard that pins the alias-vs-relative collapse directly, independent of any one subject file.
