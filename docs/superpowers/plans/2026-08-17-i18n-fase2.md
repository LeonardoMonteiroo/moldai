# i18n Fase 2 (lib strings → catalog via injected translator) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the pt-BR strings currently hardcoded inside `lib/` (drafters, conflict detection) and `TechSheetTab`'s enum maps into the `next-intl` catalog (`messages/pt-BR.json`), via an injected translator function (`Translate`), so `lib/` stays framework-free and the persisted `Molde` JSON blob shape is unchanged (no reset migration).

**Architecture:** A `Translate` type (`lib/i18n/translate.ts`) is the only contract `lib/` code depends on — next-intl's `t` (from `getTranslations`/`useTranslations`) is structurally assignable to it, so callers pass `t` straight through, no adapter. Server code (route handlers) obtains `t` via `getTranslations("PatternData")` and threads it through `applyGarmentSpec`/`refitSleeve` → `draftGarment` → `draftBody`/`draftSleeve`/`draftSkirt` → `detectConflict`. Client code (`Footer`, `TechSheetTab`, `CutPlanTab`) obtains its own `t` via `useTranslations("PatternData")` and threads it through `exportPattern`/`buildExportModel`/`planCutLayout`. Drafters still emit resolved strings, so the persisted blob shape is unchanged.

**Tech Stack:** Next.js 16, TypeScript, next-intl 4.13.7 (single-locale pt-BR, no routing), Vitest.

## Global Constraints

- Every migrated catalog value must be byte-identical to the current hardcoded literal (same accents, curly quotes `“ ”`, middot `·`, no wording changes).
- `lib/` code must never import `next-intl` — only the `Translate` type from `lib/i18n/translate.ts`.
- The persisted `Molde` JSON blob shape must not change — no reset migration for this phase.
- `t` is passed alongside existing logic and changes no control flow, no credit flow, no conflict-detection math.
- Model id references, credit flow (debit→draft, refund on decline/clarify/error, HTTP 402 with no debit/no AI call), and `validateSpec`/`validateQuestions` clamping are untouched by this work.
- Verify with `npm run build`, not bare `tsc` (bare tsc gives a spurious `app/layout.tsx` LayoutProps error in Next 16).
- Lint scoped to `app lib components` (`npx eslint app lib components`) — repo-root lint false-alarms on nested `.claude/worktrees`.
- Commit messages in English, Conventional Commits (`type(scope): summary`).
- Out of scope (won't-fix): `lib/ai.ts` system prompt / AI `assistantMessage` text, numeric formatting (`cm()` stays as-is), and the hardcoded pt-BR chat message in `app/api/pattern/conflict/resolve/route.ts` (`"Copa da manga refeita..."`) — that's AI-adjacent chat text, same category as `assistantMessage`.

Replace the function signature (insert `t` before the defaulted `_opts`) and the `detailRows`/piece name:

```ts
import { Measurements } from "@/lib/measurements";
import { DetailRow, GarmentStyle } from "@/lib/types";
import { DraftedPiece, Pt } from "./core";
import { BlockOpts } from "./body";
import type { Translate } from "@/lib/i18n/translate";

const cm = (v: number) => `${v.toFixed(1).replace(".", ",")} cm`;

export function draftSleeve(
  m: Measurements,
  style: GarmentStyle,
  armholeLenCm: number,
  t: Translate,
  _opts: BlockOpts = { gender: "female", knit: false, lengthCm: 0 },
): DraftedPiece | null {
  if (style.sleeve === "none" || !style.sleeve) return null;
  const bicep = armholeLenCm * 0.9;
  const capH = armholeLenCm / 3;
  const len =
    style.sleeve === "long" ? m.longSleeveLength : m.shortSleeveLength;
  const hemHalf = (bicep / 2) * (style.sleeve === "long" ? 0.7 : 0.9);
  const cxTop = bicep / 2;

  const outlineCm: Pt[] = [
    [0, capH],
    [bicep * 0.2, capH * 0.3],
    [cxTop, 0],
    [bicep * 0.8, capH * 0.3],
    [bicep, capH],
    [cxTop + hemHalf, capH + len],
    [cxTop - hemHalf, capH + len],
  ];
  const curvedSpans: [number, number][] = [[0, 4]];
  const grainlineCm: [Pt, Pt] = [
    [cxTop, 3],
    [cxTop, capH + len - 3],
  ];
  const detailRows: DetailRow[] = [
    { label: t("rows.sleeveType"), value: t("sleeveType." + style.sleeve) },
    { label: t("rows.length"), value: cm(capH + len) },
    { label: t("rows.sleeveCap"), value: cm(armholeLenCm) },
    { label: t("rows.grain"), value: t("grainValue") },
  ];
  return {
```
