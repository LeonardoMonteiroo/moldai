## What this is

MoldAI is an AI pattern-making product for clothing (chat with an AI to generate/adjust 2D sewing patterns, grade sizes, export to Audaces/Molde.me/plotter/PDF). This repo currently implements **only the pattern editor screen** — the single most complex screen of a larger design handoff — as a self-contained Next.js app with a mocked backend. The chat is backed by a **real Anthropic API call** (`claude-sonnet-5`) that interprets requests and returns a `GarmentSpec` (garment type + measurement overrides + style); the server validates/clamps that spec and **drafts** the pattern pieces from it. The rest of the backend (credits, grading, billing, conflict persistence) is still a mock in-memory store, and there is no auth. Requires `ANTHROPIC_API_KEY` in `.env.local`.

Dashboard, landing, onboarding, plans, import, export, version history, and measurement-grid screens are explicitly out of scope for the current state of this codebase.

## Architecture

**Everything server-side is a mock.** `lib/mock-data.ts` holds one module-level in-memory `EditorState` (pattern, pieces, chat, credits, active conflict) seeded on server start and mutated in place by the route handlers under `app/api/`. There is no database — state resets on server restart, and each mutator function (`addMessage`, `debitCredits`, `refundCredits`, `bumpVersion`, `setConflict`, `applySizes`, `applyPurchase`) is the single place that changes that slice of state.

**The editor opens on a blank molde.** `seedPattern` starts with **no pieces**, empty chat, name "Novo molde", and `version: 0` — so the user always generates from scratch. The garment's pieces (a variable set — e.g. frente/costas/manga for a blusa, plus a saia piece for a vestido) are created by the **first** AI generation, which drafts a full `GarmentSpec` and hands it to `draftGarment`. `CanvasArea` shows a "Molde em branco" empty state and hides the floating toolbar while `pieces` is empty; `store.sendMessage` auto-selects the first piece once a generation produces one.

**API routes simulate real backend behavior**, not just return static data:
- `POST /api/pattern/generate` — debits `COSTS.adjust` immediately, then calls `proposeGarment` (`lib/ai.ts`) which asks `claude-sonnet-5`, via forced tool-use, for a `{ decision: "apply" | "decline", spec, declineReason?, assistantMessage }`. The returned `spec` is never trusted as-is: `validateSpec` (`lib/draft/garment.ts`) re-checks every enum and clamps every numeric field before use. `apply` runs `applyGarmentSpec`, which calls `draftGarment(spec, size)` to recompute `pieces`/`viewBox`/`baseMeasurements` from scratch and bumps the version; `decline` and any API/parse error refund the credit. Conflict detection is currently a no-op — `draftManga` sizes the sleeve cap from the corpo's armhole (`armholeLenCm`), so the two seams match by construction — but `seamCheck` (`lib/draft/garment.ts`) exists as the seam-length comparison an active conflict check would use if a garment ever let them diverge. Insufficient balance returns HTTP 402 (no debit, no AI call).
- `POST /api/pattern/graduate`, `POST /api/pattern/conflict/resolve`, `POST /api/billing/purchase` follow the same debit-then-mutate pattern; grading and purchase both 402 the same way generate does.

**Client state lives in one Zustand store** (`lib/store.ts`, `useEditorStore`): it mirrors the server's `EditorState` after every mutating call and additionally owns UI-only state (active tab, selected piece, details-panel open, active tool, generation status/step, and the paywall's open/required/retry state). All server calls go through `lib/api-client.ts`; components never call `fetch` directly. `sendMessage` optimistically appends the user's chat message before the request resolves, and `cancelGeneration` rolls that optimistic message back and refunds the cost client-side (there's no server-side cancel).

**The paywall is action-agnostic.** Any store action that can fail on insufficient credits (`sendMessage`, `graduateSizes`) stores its own retry closure in `paywall.retry`. `purchase()` applies the mock purchase, closes the modal, and invokes whatever `retry` was stashed — so "buy credits then automatically finish what I was doing" works for any future paid action without new plumbing, as long as it follows the same "set paywall state with a retry thunk" pattern.

**Design tokens live in `app/globals.css`** as Tailwind v4 `@theme` variables (colors, radius, shadow scale) rather than a `tailwind.config.ts` — this project has no JS Tailwind config file. Fonts (Bricolage Grotesque for display/titles, Archivo for UI/body) are loaded via `next/font/google` in `app/layout.tsx` and exposed as the same kind of CSS variables. When adding new colors/spacing, extend the `@theme` block, don't hardcode hex values in components.

**Two floating panels compete for the same canvas slot**: `PieceDetailsPanel` and `ConflictInfoCard` both render top-right over the pattern canvas in `CanvasArea.tsx`. They are mutually exclusive by design — a conflict always takes over that slot — so new canvas overlays need to be folded into that same exclusivity check rather than added as a third independent floating panel.

**Pieces are drafted from measurements, not deltas.** `lib/measurements.ts` defines `Measurements` (busto, cintura, ombro, etc.) and a `SIZE_TABLE` of base values per `SizeLabel` (PP–GG); `resolveMeasurements(size, overrides)` starts from the size row and applies chat-driven `measurementOverrides`, clamped to `MEASUREMENT_RANGES`. A `GarmentSpec` (`tipo` + `measurementOverrides` + `style`) plus a size flow into `draftGarment` (`lib/draft/garment.ts`), which calls the per-block drafters in `lib/draft/*` (`corpo.ts`, `manga.ts`, `saia.ts`, shared helpers in `core.ts`) to build each `Piece`'s outline/guide/grainline/dart in cm and lay them out into a single computed `viewBox` (`autoLayout`). The AI never emits SVG or pixel coordinates — it only returns a `GarmentSpec`, which the server always re-validates and clamps via `validateSpec` before drafting, regardless of what the model returned. The old fixed `PieceDetails` (folgaCostura/penceBusto/cava/fio/consumo) is gone; each drafter instead attaches whatever `piece.detailRows` (label/value pairs) make sense for that piece.
