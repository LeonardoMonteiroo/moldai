## Fix Plans

### Fix 1: Width-delta formula has no exact-value regression test

- **Root cause**: `lib/draft/body.test.ts`'s "BDART-02: dart width grows monotonically with a larger cup delta" test (line 676) and the "BDART-01/02" test (line 592) only assert directional growth (`toBeGreaterThan`), never pin the cited FBA formula's exact coefficient (`bustCupDeltaCm / 4`). A mutation to that divisor passes `body.test.ts` in full (51/51) and is only caught, incidentally, by an unrelated pre-existing `#132` persona fixture in `garment.test.ts` whose containment check happens to break at the mutated (wider) width — a coincidence, not a designed safety net for this formula.
- **Fix task**: Add one exact-value assertion to `lib/draft/body.test.ts`'s bust-apex describe block, e.g. asserting `dartHalfWidth * 2` (the detail-row value, or the leg-to-leg width) for `HIGH_BUST_DELTA` (`bustCupDeltaCm = 8`) equals the hand-derived value under the cited `/4` formula (existing `dartsSuppression/8`-derived half-width `+ 8/4 = 2`), the same "hand-derive independently of the implementation" discipline the file's `EXPECTED_APEX` comment already documents for the apex position.
- **Priority**: Minor — the spec's own AC2 ("strictly monotonically") is satisfied by the existing directional test; this is a test-strength gap against the _design's_ cited formula, not a failed spec AC. Recommended before closing the feature, not a blocker.

### Fix 2: Edge Case 2 (independent field resolution) has no dedicated test

- **Root cause**: Every test exercising a real `bustSpan`/`bustPointHeight` value sets both fields together; none isolates one while leaving the other `undefined` to prove they resolve independently (each via its own `??` fallback in `lib/draft/body.ts:355-356`).
- **Fix task**: Add a case to `lib/draft/body.test.ts`'s bust-apex describe block setting only `bustSpan` (leaving `bustPointHeight` unset) and asserting the apex Y-coordinate matches the fallback constant (26.5-derived) while the X-coordinate matches the real value — and the mirror case for `bustPointHeight` alone.
- **Priority**: Minor — code inspection shows the two fallbacks are structurally independent (`m.bustSpan ?? 18.5` and `m.bustPointHeight ?? 26.5` are separate expressions), so risk of an actual defect is low, but the spec explicitly calls this out as an edge case requiring verification.

### Fix 3: Edge Case 3 (non-fitted panel with a real delta) has no dedicated test

- **Root cause**: No test combines `knit: true` (or `style.darts: false`) with `highBust < bust` to confirm the `if (fitted)` gate keeps the entire bust-apex code path inert (no dart, no crash) when there's nothing to shape.
- **Fix task**: Add a case to `lib/draft/body.test.ts` drafting a knit/t-shirt-style panel (`knit: true` in `BlockOpts`, or `darts: false`) with a real `highBust < bust` and asserting `front.internalsCm` contains no `dart`/`foldLine` entries, matching the same-shape assertion the file already uses elsewhere (`dartsOf(...)`).
- **Priority**: Minor — the `if (fitted)` gate is a pre-existing, unmodified structural guard, so this is a low-risk documentation-completeness gap.
